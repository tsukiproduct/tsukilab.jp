# プロンプト③: まとめて数本作る(ショートと予約表つき)

`---` から下を貼ってください。

---

`{{フォルダ名}}/CLAUDE.md`、`CHANNEL_SPEC.md`、`topics.json` を読み、その方針どおりに {{7}} 本をまとめて作ってください。
題材は直近 {{7}} 日のトレンドから、数字が取れそうなものを選んでください。

## 手順
1. **題材の一覧を先に出す**: 候補10個に、需要(同テーマ上位10本の再生数の中央値)・ニュースの日付・出典・
   重複チェックの結果を付けて並べ、選んだ {{7}} 本とその理由を示す。
2. **1本ずつ制作**: 各回 `03_PROMPT_episode.md` の手順2〜5を行う。書き出しは時間がかかるので、
   順番待ちのスクリプトで裏で回し、完了・エラーを監視しながら、終わった回から確認する。
3. **ショート**: 各回2本(本編の切り抜き)と、ショート用の縦型サムネイル(9:16)を1本につき1枚。
4. **投稿の予約表**(`PUBLISH_SCHEDULE.md`):
   - **回の番号 = 公開順**にする(番号を振ってから制作する。後から順番を入れ替えない)。
   - 本編は1日1本。公開時刻は視聴のピーク(日本は21〜22時)の1〜2時間前。ショートは本編の翌日の昼と夜。
   - 並べ順は「ニュースの新しさ」「需要」「曜日(週末に需要の大きい回)」で決め、理由を書く。曜日はカレンダーで確かめる。
   - Studio での手順(タイトル・概要欄・サムネA・予約、ショートの関連動画、公開後にテストと比較でB・Cを追加)を書く。
5. **渡す**: 公開順に、回ごとに「本編 / ショート1 / ショート2 / サムネとテキストのzip」を送る。
   最後に、全ファイルの一覧と予約表、PCで回ごとのフォルダに整理するスクリプト(Windows なら PowerShell。
   UTF-8 BOM・CRLF)を付ける。
6. **報告**: 各回の題材・需要の数字・出典、確認中に直したこと、残っている注意点を表で伝える。
