# この世界のバグ図鑑 運営仕様書

方針をぶらさないための決まりごと。迷ったらこの文書に従い、変えるときはこの文書を先に直す。

## 1. コンセプト
- **チャンネル名**: この世界のバグ図鑑
- **一言で**: ニュースで見つかった「この世界の仕様の不具合」を、ずんだもんと春日部つむぎが毎日報告する。
- **差別化**: 毎回を「バグ報告書 No.XXX」として扱い、最後に**ステータスの判子**を押す。
  単なる謎の読み上げにしない(収益化の「量産型」判定を避ける要)。
- **ステータスの語彙(固定)**: 未解決 / 調査中 / 仕様です / 修正済み / 修正パッチ配布中 / 誤報でした
- **アイコン**: 案A(2人の顔 +「バグ」)。バナーは `tools/brand.py` で作成。

## 2. キャラクターと役割
| キャラ | 位置 | 役割 | 話し方 |
|---|---|---|---|
| 春日部つむぎ | 左・右向き | 報告係。落ち着いて事実を伝え、ツッコむ | 丁寧語。短い文。断定は出典があるときだけ |
| ずんだもん | 右 | 視聴者の代弁。知ったかぶりで外す、驚く | 「〜なのだ」。素直で少しおバカ |

- 声: VOICEVOX ずんだもん(ノーマル, 速さ1.05, 抑揚1.15)/ 春日部つむぎ(ノーマル, 速さ1.0, 抑揚1.1)
- 笑い: つむぎの淡々とした一言ツッコミ(「不正解です。」「盛れるカメラです。」)、ずんだもんの的外れな推理。
  管理人ネタ(確認しないと眠れない、など)は**たまに**使う。毎回は使わない(型の固定を避ける)。
  人や国、宗教、属性を笑いの対象にしない。

## 3. 1話の構成(目安 3〜6分。慣れたら8〜12分へ)
1. **フック(〜20秒)**: 挨拶より先に「バグ」を見せる。答えは最後に出すと予告する。
2. **オープニング(2.6秒)**: ロゴ + 「バグ報告 #番号」。冒頭0秒には置かない。
3. **挨拶(全身)**: 2行だけ。
4. **章(上部の章バー、4章)**: 例「バグ → 原因 → 修正/正体 → 報告」。章の名前は話ごとに変えてよい。
5. **見せ場**: 毎話1つ以上、動きのある図(アニメ・3D・地図・比較)を入れる。静止画の羅列にしない。
6. **報告書カード → 判子**。
7. **締め**: コメントでの「バグ報告」募集 → チャンネル登録(価値を見せた後にだけ頼む)。

**毎話変えるもの**: 題材、結論、章の名前、見せ場の種類、笑いの入れ方、ステータス。
**毎話同じでよいもの**: オープニング、挨拶、報告書カード、締めの言い回し(公式ポリシーでも「イントロとエンディングが同じでも、大部分が異なれば可」)。

## 4. 題材の選び方
- 優先: **直近1か月のニュース × 昔からの定番の疑問**が重なるもの(例: 国連決議 × 世界地図の大きさ)。
- 公開前に需要を見る: YouTube検索(再生回数順、全期間と今年)で同テーマの上位10本の再生数を確認し、`topics.json` の `demand` に記録する。
- タイトルで伸びた型(実データ): 「なぜ/理由」(約1.9倍)、「ヤバい/衝撃」(約1.75倍)。「N選」の羅列型は弱い(約0.5倍)。
- **扱わない**: 健康・医療・金融・法律の助言になる話題(AIキャラによる扱いは収益化の対象外と明言されている)、
  事件の被害者を見世物にする話、真偽不明のオカルトを事実として語る話。
- 同じ題材・同じ結論の重複は禁止。新しい題材は必ず `python3 tools/topics.py check "キーワード"` で確認してから着手する。

## 5. 事実確認のルール
- 台本の数字と固有名詞は、すべて出典を1つ以上確認する(できれば一次情報: 論文・公的機関・公式発表)。
- 確認できない数字は使わない。仮説・推測は「〜という説」「〜かもしれません」と明示する。
- 出典は台本JSONの `sources` に書き、概要欄に自動で載る。
- 誤りが分かったら、概要欄と固定コメントで訂正する。

## 6. 画像・音のルール
- 使ってよい: 自作の図(地図・3D・グラフ)、パブリックドメイン、CC0、CC BY(出典表記)。
- 使わない: CC BY-SA(動画への適用に解釈の幅がある)、CC BY-NC、権利が不明な画像、報道写真。
- 生成AIの画像は「イメージ図」と明記。実写風で実際の出来事を描くものは YouTube の「改変・合成コンテンツ」表示をオンにする。
- BGM: 発話中は声よりBGMが約20dB小さい(自動ダッキング)。仕上がり -16 LUFS。曲は `assets/bgm/sources.json`。
- クレジット(音声・立ち絵・画像・BGM・参考文献)は**概要欄**に載せる。動画内は画像の出典だけ。

## 7. タイトル・サムネイル・概要欄
- タイトル3案、サムネ3案を毎回作り、YouTube Studio の「テストと比較」に入れる(勝敗は表示1回あたりの総再生時間)。
- サムネ: 大きな顔と強い表情 / 見出しは8文字前後・2行まで / 高コントラスト / 右下に何も置かない /
  シリーズ共通の黄色と「バグ報告 #番号」札 / タイトルと同じ言葉を繰り返さない。
- 中身と合わない煽りは禁止(満足度の低い視聴は推薦で不利になる)。
- 概要欄: 冒頭2行で要約 → チャプター(0:00始まり・3つ以上・各10秒以上、実測値から自動) → 報告書 → コメント募集 → クレジット → ハッシュタグ3つ。

## 8. 投稿と収益化
- **1日1本**。一度に複数本を公開せず、YouTube Studio の予約投稿で間隔をあける。
- 収益化の条件は **2027年2月1日から2倍**(登録者1,000人 + 総再生8,000時間/12か月 または Shorts 2,000万回/90日)。
  それ以前に参加したチャンネルはそのまま継続できる → 2027年1月末までの審査通過を最優先の目標にする。
- 月1回、過去回をまとめた「寝ながら聴ける」総集編を作る(再生時間を稼ぐ役)。
- Shorts: 長尺1本から1〜2本の予告を切り出し、長尺へ誘導する(今後ツール化)。

## 9. 振り返り(週1回)
- 各動画の 0:30 時点の視聴維持率、章の切り替わりでの離脱、クリック率、テストと比較の結果を見る。
- 良かった型・悪かった型を `topics.json` の `notes` に書き、この仕様書を更新する。

## 10. 制作コマンド
```
python3 tools/topics.py check "キーワード"                # 題材の重複確認
python3 scripts/build.py scripts/epXXX_*.json --voice-only  # 声の合成(VOICEVOXが必要)
python3 scripts/build.py scripts/epXXX_*.json --use-wavs --out out/epXXX.mp4
python3 scripts/package.py scripts/epXXX_*.json            # サムネ3案・タイトル・概要欄
```
