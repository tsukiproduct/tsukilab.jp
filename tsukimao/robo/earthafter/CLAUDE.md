- いま作っているのは新しい物語（仮題「声を無くしても、あなたを愛している」）。旧作『EARTH AFTER』は 2026-11-08 に凍結した。
- 成功の条件は三つ。
  1. 二十分以内の映像として、通しで観て成立していること（関門に不合格がない）。
  2. 規定を満たして、期限内に提出できていること。
  3. 月真猫さんが決めたことだけが「確定」として残り、Claude の案と混ざっていないこと。

## 2. いちばん大事な教訓

旧作は、紙の上の採点で 87/100 だった。全編を生成して繋いだら「二十分に収まらない、切り抜きの寄せ集めの総集編」だった。
原因は、(a) 脚本の出来を測り、映像として成立するかを測らなかった、(b) 観ていないものに見込みで点を付けた、(c) 作った本人（Claude）が採点した、の三つ。

だから次を守る。

- **点数より先に関門。** `review/data.js` の十二の検査に不合格があるうちは、点数を語らず、物語を直す。
- **観ていないものに点を付けない。** 段階ごとの上限は、骨子 22、脚本 40、絵コンテ 60、映像 100。「百点満点で何点」と言わず、「この段階の上限◯点のうち◯点」と言う。
- **自分の採点を信用させない。** 客観的な評価を求められたら、自分は公平な立場でないと先に述べ、事情を知らない別のエージェント三者に物語の本文だけを読ませ、結果を良いものも悪いものもすべて並べる（やり方は `review/#mouken`）。
- **通しで観るまで仕上げない。** 720p の粗い通し版を全員で観る前に、高解像度化や細部の直しへ進まない。
- 褒めるより、危ないところを先に言う。月真猫さんは「心を打つ作品は苦手」と自認されており、率直な指摘を求めている。

## 3. 確定・提案の書き分け（破ってはいけない決まり）

| 区分 | 意味 | 置き場所（`story/data.js`） |
|---|---|---|
| 確定 | 月真猫さんかチームが決めたこと。出典（誰が・いつ）必須 | `kakutei` |
| 引き継ぎ候補 | 旧作の決定で、新しい物語で使うか未確認 | `hikitsugi` |
| 提案 | Claude の案 | `teian` |
| 仮定 | 未定のため仮に置いた値 | `katei` |
| 未決定 | 月真猫さんに決めていただく問い | `mitei` |

- 月真猫さんが言っていないことを `kakutei` に入れない。自分の提案が採用されたら、採用の日付を出典にして `kakutei` へ移し、`teian` から消す。
- 問いに答えをいただいたら、`mitei` から消して `kakutei` に書く。関わる関門の判定（`review/data.js` の `neo`）も直す。
- チームの雑談や思いつきは捨てず、`ideas`（裏設定・アイデア帳）に残す。物語を縛らない。
- 月真猫さんの物語を、頼まれていないのに書き換えない。矛盾や隙間を見つけたら、直さずに知らせる。

## 4. 月真猫さんに確認が要ること／確認なしでしてよいこと

確認が要ること：
- 物語の中身に関わる変更すべて。確定事項の変更。
- **絵・動画・音の生成**（明示のお指図があるまで一切しない）。生成は課金される。
- 制作室の内容の更新（まず「更新候補」として知らせ、了承を得てから直す）。誤字や壊れた表示の修理は知らせるだけでよい。
- 既存ファイルの削除や移動。外部への投稿や送信。
- ログイン、パスワードの入力（ご本人にお願いする）。

確認なしでしてよいこと：
- 調べもの、点検、下書き、控えを取ること。提案を `teian` として書き添えること（了承後に公開）。

## 6. 直すときの手順

1. 大きな変更なら、先に `_backup/日付_内容/` へ文字のファイル（html/js/css/json/md/py）を控える。
2. 正本（`story/data.js` か `review/data.js`）を直す。同じ内容をページの HTML に二重に書かない。
3. 関わるページを漏れなく直す（段取りを動かしたら `record/#nagare` も。規定が変わったら `rules/` と `review/` も）。
4. 版を上げる：`assets/ea-nav.js` の `VER` と、各 HTML の `?v=` を揃えて上げる（`story/data.js?v=`、`review/data.js?v=`、`ea-core`、`ea-nav`）。
5. `python3 assets/build_index.py`（BeautifulSoup が要る）。
6. `python3 assets/check.py` が「問題は 0 件」になること。
7. ブラウザで全ページを 390px と 1280px で開き、コンソールのエラー、横あふれ、崩れがないことを確かめる（Playwright が入っている。`python3 -m http.server` をリポジトリの根で起動）。フォントの読み込み失敗は作業環境の通信制限によるもので、無視してよい。
8. コミットして公開：
   `git -c user.name=tsukiproduct -c user.email=tsuki.product@gmail.com commit` のあと
   `git fetch -q origin main && git rebase -q origin/main && git push -q origin HEAD:main`

旧作のデータ（`data.js` と `script/data.js`）は、カットの順と合計秒数が一致していないと旧ページが崩れる。凍結したので触らないこと。

## 7. 文章と見た目の決まり

- サイトの文章は日本語だけ。英語の見出しや文を混ぜない。丁寧で落ち着いた語調。
- 状態は、色・線の種類・ことばの三つで示す（`ea-core.css` の `.st-k/h/t/a/m`）。色だけに頼らない。
- 見た目の考え方は「電波の届かない部屋の、夜の灯り」。壁は鉛色、文字は生成り、強調は灯りの色ひとつ。新しい飾りを足さない。
- 推測は推測、未確認は未確認と書く。数字の閾値には根拠を添える。
- スマホ（390px）で横にあふれないこと。押せるものは高さ 44px 以上。

## 8. 制作の流れ（詳しくは `record/`）

物語 →【骨子の関門】→ 脚本 → 絵コンテ → 720p の粗い通し版 →【通しで観る】→ 直しと音 → 高解像度化と書き出し →【通しで観る・確認表】→ 提出

月真猫さんが決めたやり方（確定）：
- 動画は BytePlus Lumina（Chrome 上）で Seedance 2.0 mini・720p・16:9。全体を粗く作ってから直し、1080p へ高解像度化。難所は Seedance 2.5 や Vidu 4。Kling はなるべく避ける。
- 絵コンテは動画の最初のコマにせず、参考（omni）素材として渡す。参考の絵が崩れていたら、月真猫さんがChatGPTで直すので、直し用のプロンプトを用意する。
- 絵コンテの絵は月真猫さんがChatGPTで作る。依頼はプロンプトと素材をZIPにまとめる。物語の絵は一枚を2×2の四分割、設定画は一枚ずつ。この依頼一式は制作室に載せない。
- 検閲で弾かれたら、言い回しだけ変える。画面や物語が変わる直しはしない。質を落とさない。静止画で代用しない。
- 台詞は口の動きと一致させ、ひらがなとローマ字を添える。

## 9. 規定で忘れやすいこと（詳しくは `rules/`）

- 提出は H.264、横 16:9、1920×1080 以上（2160p 推奨）、30fps 推奨、−14 LUFS 目安、25GB まで。
- **AIの出力をそのまま出すのは禁止。** 編集や加工の内容を説明できるようにする。
- **制作記録の開示義務（規約第九条）。** カットを作るたびに、モデルとバージョン、プロンプト、パラメータ、シード値、参考素材、採否、手を入れた内容を残す。Claude が生成を操作したときは、作業の終わりに表で渡す。保管場所は未決定（Q13）。制作室は誰でも開けるので、記録をここに置かない。
- 既存作品のプロットをなぞった作品は評価対象外。先行作との違いを言えるようにする（関門 G12）。
- 声の合成サービスや曲の生成道具の利用規約は未確認。決まり次第確かめる。断定しない。
- 規定は変わることがある。提出の前に公式ページを開いて見比べる。
