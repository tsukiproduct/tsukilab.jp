# ゲームフロー説明（実装の現状）

`docs/SPEC.md` は「こう作る」という設計書。こちらは**「今どう動いているか」**を書いたもの。
仕様書と実装が食い違っている箇所は §6 に一覧で挙げてある。

---

## 1. 1ゲームの流れ

```
① BET（3枚）
     ↓
② レバーON  ← ここで内部抽選（1/65536の乱数を1個引く）
     ↓        この瞬間に「今回何が当たったか」は確定している
     ↓        リールを止める操作では結果は変わらない
③ 演出（カットイン・フラッシュ）
     ↓
④ リール3つを停止  ← 制御表に従い、成立役を最大4コマすべりで引き込む
     ↓
⑤ 入賞判定・払い出し
     ↓
⑥ ボーナス入賞していれば → ボーナスへ
   していなければ → ①へ
```

**重要**: パチスロは「レバーを叩いた瞬間に当たりが決まる」方式。目押しは
「当たっているものを取りこぼさないため」の技術であって、目押しで当たりを増やすことはできない。

## 2. 何が当たるのか（成立役）

レバーONで、以下のどれか1つが選ばれる（設定1の確率）。

| 成立役 | 確率 | 何が起きるか |
|---|---|---|
| リプレイ | 1/7.3 | 次ゲームのBETが不要 |
| ベル | 1/6.6 | 8枚（AT中はナビが出て11枚） |
| 弱スイカ | 1/126 | 15枚（右下がりに揃う） |
| 強スイカ | 1/381 | 15枚（中段に揃う。約27%でボーナス重複） |
| チェリー | 1/41 | 2枚 |
| 1枚役 | 1/252 | 1枚 |
| チェリー+BIG | 1/1638 | 2枚 ＋ **BIG成立** |
| チェリー+REG | 1/2731 | 2枚 ＋ **REG成立** |
| スイカ+BIG | 1/2185 | 15枚 ＋ **BIG成立**（強スイカ扱い） |
| スイカ+REG | 1/4096 | 15枚 ＋ **REG成立**（強スイカ扱い） |
| 1枚役+BIG | 1/1638 | 1枚 ＋ **BIG成立** |

## 3. ボーナスが当たってから始まるまで

パチスロ特有の**2段階**になっている。ここが分かりにくいポイント。

```
【ステップ1】ボーナス成立（内部当選）
   レバーONでボーナスフラグを引く。
   でも、この時点ではまだボーナスは始まらない。
   画面には「チャンス!?」と出て、背景が前兆ステージに変わる。

        ↓ このあいだ「内部中」と呼ぶ。何ゲームか続くことがある
        ↓ 途中で「確定演出」が走ると告知される（下記）

【ステップ2】ボーナス入賞
   ボーナス図柄（赤7揃い or BAR揃い）が実際に中段に揃うと発動。
   現在の実装は「オートビタ」なので、内部中にハズレを引いた
   次のゲームで自動的に揃う。
```

### 確定演出（カットイン→溜め→濃厚）

内部中のどこかで、3段構成の告知演出が走る。

```
① カットイン   強カットインの帯が液晶に飛び込む（0.5秒）
② 溜め         画面が細かく震えて「!?」が出る（0.9秒）
③ 濃厚         フラッシュ＋「BONUS 濃厚」（1.5秒）
```

- **成立ゲームで45%**、外れたら**内部中の毎ゲーム8%**で抽選し続ける（平均12G前後で告知）
- **BIGかREGかは出さない**。種別が分かるのは入賞したときの告知画面から（実機と同じ）
- 告知後はバッジが「ボーナス濃厚」になり、毎ゲーム「7を狙え!!」が出続ける
- デバッグパネルの「確定演出」ボタンでいつでも再生できる

**リーチ目**: 単独BIG/単独REGを引いたゲームでは、左リールに7かBARが見えて
何も揃わない出目（＝リーチ目）が出る。この出目はハズレでは絶対に出ないように
制御しているので、**見えたらボーナス確定**。560通りある。

## 4. ボーナス中

**ボーナス中も自分でリールを打つ。** 消化役を毎回引き込むので取りこぼしは無い。
BET（3枚投入）は不要。液晶には**累計獲得枚数が大きく出る**。

その背景は動画の有無で変わる。

- 選択中の楽曲MV（`mv_song1` / `mv_song2`）があれば → **音アリでループ再生**（音量0.75）
- 無ければ → 従来どおり告知画面の静止画を固定表示

BIGは14ゲーム＝1分前後なので、2分以上のMVならループ点は踏まない。
自動再生ポリシーで音アリ再生が弾かれた場合はミュートで鳴らし直すため、映像が消えることはない。

**MVはAT中もそのまま流れ続ける。** ボーナス→AT は同じキーなので途切れない。

REGだけは映像を持たず、`assets/se/bgm_reg.mp3` をループする。

### 楽曲選択

BIG中とAT中に流すMVを2曲から選べる。

| | |
|---|---|
| いつ選ぶか | **BIG開始前に自動で1回**（無操作なら9秒で今の選択のまま開始）／ **AT中は液晶左下の♪ボタンからいつでも** |
| 曲 | 01「回胴式の魔法」 ／ 02「ひきよわヒーロー」 |
| 保存 | `localStorage` に残るので次回も同じ曲で始まる |

画面デザインだけは本体のレトロ4号機トーン（`docs/STYLE.md`）から意図的に外し、
赤×黒×白・斜め・切り抜き文字で構成している。液晶の中のUIとして浮かせる狙い。

### リザルト画面

**ボーナスの最終ゲームでMVを止め、止めるのと同時にリザルト画面に切り替わる。**

| | BIG / REG 終了 | AT 終了 |
|---|---|---|
| 見出し | `BIG BONUS 終了` | `MOON TIME 終了`（完走時は`完走`） |
| 数字 | 獲得枚数（204 / 60） | AT中の差枚（`+181`など） |
| 補足 | ビタ押し n/3 成功 ／ AT当選の可否 | 消化ゲーム数 |

AT終了時も同じくMVを止めてから出す。**通常に戻ったあとMVの音が残らない**のはここで
`setLoopMovie(null)` を通しているため（`setLoopMovie` は切替時に必ず前の動画を pause する）。

### BIG BONUS
- 赤7揃いで発動
- 1ゲーム **15枚**（スイカ揃い）
- 累計 **204枚** に到達したら終了 → **14ゲーム**（最終ゲームは端数の9枚）
- **5G目・9G目・13G目に「ビタ押しチャレンジ」**が発生（計3回）
- 終了時のAT当選率はビタの成功回数で変わる（下表）

### REG BONUS
- BAR揃いで発動
- 1ゲーム **8枚**（ベル揃い）
- 累計 **60枚** に到達したら終了 → **8ゲーム**（最終ゲームは端数の4枚）
- 技術介入なし
- 終了時に **1/16でAT当選**（当選時30G）

### ビタ押しチャレンジ（BIG中の技術介入）

「中リール 赤7を狙え！」と表示されたら、**中リールの中段に赤7が来る瞬間に停止ボタンを押す**。
**±1コマまで成功**。このゲームだけは制御でのすべりが効かず、押した位置がそのまま結果になる。

| ビタ成功回数 | 0回 | 1回 | 2回 | 3回 |
|---|---|---|---|---|
| AT当選率 | 40% | 55% | 70% | **AT濃厚** |
| 獲得G数 | +6G | +14G | +22G | +30G |

失敗しても救済で+2G/回が乗るため、全外しでも40%のAT抽選は受けられる。
BIG入賞時の1/64で発生する**フリーズはビタの結果に関わらずAT濃厚＋50G**。

> ボーナス中のゲームは投入不要なので、払い出し総枚数（204 / 60）がそのまま純増になる。
> これは `tests/simulate.js` の計算モデル（投入なしで一括加算）と一致している。
> AT当選率を50%→40%（全外し時）に変えたことで機械割は約0.4pt下がった
> （設定1: 95.4% → 95.0%）。技術介入の価値を出すための意図的な変更。

## 5. AT「MOON TIME」

- 純増 **約+0.5枚/G**（リプレイ確率アップ＋押し順ベルナビ）
- 初期 **BIG経由20G / REG経由16G**（＋BIG中のビタ獲得分、最大+30G）
- 終了条件: 残りG数が0、または AT開始からの差枚+2400 / 1500G消化（完走）
- 残り3ゲームからカウントダウン（3 → 2 → LAST）

初期G数は少なく、**上乗せで伸ばしていく**構成。
メインの65536テーブルはAT中も一切変わらない。

### AT中の上乗せ

| 契機 | 当選率 | 上乗せ |
|---|---|---|
| チェリー | 1/4 | +10G |
| 1枚役 | 1/2 | +20G |
| 弱スイカ | 1/8 | +30G |
| **強スイカ** | **1/2** | **+50G / +70G / +100G**（均等・期待値約73G） |
| AT中BIG | — | +30G |

抽選は `src/core/lottery.js` の `drawATUpgrade()` に置いてある。
**シミュレーターも同じ関数を通す**ので、実装とモデルがズレない。

「スイカはなかなか乗らないが乗れば大きい」を、
弱スイカ=当たりにくい小さめ／強スイカ=そもそも引きにくいが当たれば50G以上、で表現している。

### エンペラータイム（特化ゾーン）

```
突入契機  BIG中のビタ押し3回成功 → 濃厚
          それ以外のAT当選時     → 1/8

中身      1ゲームごとにルシエルの勝敗を抽選
          勝ち → +20G して継続
          負け → 終了

継続率    約80%（205/256）。平均5連 = 約100G
```

この機種で唯一、**技術介入がそのまま出玉に直結する**ゾーン。
ビタ押しを3回とも成功させれば濃厚になるので、BIG中のチャレンジは全部狙う価値がある。

演出は1戦ずつ「BATTLE → WIN! ＋20G」を見せ、負けた時点で連勝数と合計を出す。

## 6. 音

音源ファイルは持たず、`src/ui/sound.js` が WebAudio で合成している。
**役ごとに入賞音が違う**ので、目を離していても何が入ったか分かる。

| タイミング | 音 | 内容 |
|---|---|---|
| BET | `SE.bet()` | メダル投入のカチャッ |
| レバーON | `SE.lever()` | 低音が落ちるウィーン |
| リール停止 | `SE.stop()` | 短いガコッ |
| ベルなど一般の子役 | `SE.payout()` | 明るい「チン」 |
| **スイカ** | `SE.melon()` | 上昇アルペジオ（レア役らしく） |
| **チェリー** | `SE.cherry()` | 跳ねる2音＋余韻。スイカと音色を変えてある |
| 1枚役・リーチ目役 | `SE.chance()` | ざらついた2音 |
| **リプレイ揃い** | `SE.replay()` | 「ピロリン」と上がって伸びる |
| **払い出し** | `SE.medal(枚数)` | 枚数ぶん「チャリチャリ」（最大12回で打ち切り） |
| AT上乗せ | `SE.upgrade()` / `SE.bigUpgrade()` | 50G以上は別格の音にする |
| エンペラータイム | `SE.emperorStart/Battle/Win/Lose()` | 連勝ごとに音程が上がる |
| REGのBGM | `setBGM('bgm_reg.mp3')` | REGは映像がないので音のみループ |
| カットイン | `SE.cutin(1〜3)` | 弱／中／強で派手さが変わる |
| 確定演出の溜め／確定 | `SE.charge()` / `SE.reveal()` | 上昇する不安音／炸裂音 |
| **BIG入賞** | `SE.bonusStart('BIG')` | **音源ファイル** `assets/se/se_big_start.mp3` |
| **REG入賞** | `SE.bonusStart('REG')` | **音源ファイル** `assets/se/se_reg_start.mp3` |
| リザルト画面 | `SE.result()` | 3音の和音 |
| ATカウントダウン | `SE.countdown(残G)` | 3・2は2音、LASTだけ音を変える |
| ビタ成功／失敗 | `SE.vitaOk()` / `SE.vitaNg()` | 上昇4音／下降するブザー |
| フリーズ | `SE.freeze()` | 低い唸り（1.6秒） |
| AT突入 | `SE.atStart()` | 上昇5音 |

入賞音とメダル音は**重ねて鳴らす**（入賞音のあと0.12秒でメダル音が始まる）。
デバッグパネルの「演出・音のテスト」から全部個別に鳴らせる。

ブラウザの自動再生ポリシーがあるので、最初のタップ／キー入力（`markInput()`）まで
音は出ない。これは仕様。

### 音源ファイルを足すには

合成では作れない音（ボーカル入りのジングル等）は `assets/se/` に置き、
`sound.js` の `playFile('ファイル名')` で鳴らす。読めなければ `false` が返るので、
呼び元は必ず合成音にフォールバックさせること（ファイルが無い環境でも無音にならない）。

```js
const BONUS_SE = { BIG:'se_big_start.mp3', REG:'se_reg_start.mp3' };
async bonusStart(kind='BIG'){
  const file = BONUS_SE[kind];
  if(file && await playFile(file, 1)) return;
  // ...合成音
}
```

### AT終了カウントダウン

残り3ゲームから液晶の下寄せ中央に大きく出る（**3 → 2 → LAST**）。
上乗せ（AT中スイカ・AT中BIG）で残Gが増えたときは即座に消える。

## 8. 有効ライン（5ライン）

| ライン | 形 | 主な役割 |
|---|---|---|
| 中段 | ─ ─ ─ | ベル・リプレイ・1枚役・ボーナス・**強スイカ** |
| 上段 | ▔ ▔ ▔ | 出目のバリエーション |
| 下段 | ▁ ▁ ▁ | 出目のバリエーション |
| 右下がり | ＼ | **弱スイカ** |
| 右上がり | ／ | 出目のバリエーション |

**払い出しは成立した役に対して1回**で、ラインごとには発生しない。
実機はライン毎に払い出すが、そこを合わせるとテーブルのカウント値を全面的に
下げ直す必要があり、機械割の調整が5ライン化と混ざって追えなくなる。
5ラインは「出目の表現」に使う、という割り切り。

### ハズレ制御をどう成立させたか

1ライン時代は「入賞もテンパイも起こさない」を同じ強さで課していた。
5ラインで同じことをやると、4コマ以内に両方を満たす位置が無くなり、
**545通りでベルやリプレイが勝手に揃った**（総当たり実測）。

そこで2つ手を入れている。

1. **優先順位を分けた**
   - 絶対条件: どのラインも入賞させない
   - 努力目標: 生きたテンパイを作らない
   テンパイは5ラインでは正常（2リール停止時点の21.4%で発生）。
   リーチ目の一意性は左リールの7/BAR禁止だけで担保できるので、許容して問題ない。

2. **詰み回避の先読みを入れた**（`feasible()`）
   貪欲に止めていくと、押し順によっては最後の1リールがどこに止めても
   入賞する窓に追い込まれる。特に
   - ハズレで左リールが最後（中→右→左 / 右→中→左）
   - リーチ目で中リールが最後（右→左→中）
   が詰んでいた。「この位置に止めたあと、残りを全押下位置・全停止順で
   入賞させずに止め切れるか」を再帰＋メモ化で確認してから止める。

結果、`node tests/reel.js` の総当たり55,566通りで**入賞0・リーチ目漏れ0**。

### リーチ目の再定義

1ライン時代は「左**中段**に7/BAR」で足りたが、5ラインでは上段・下段も有効なので、
**左リールの3段すべて**で7/BARを禁止している。禁止すると左は21コマ中12コマしか
使えなくなるが、禁止区間は最長3コマ連続なので4コマすべりで必ず逃げられる。

### チェリー

**左リール中段のみ有効**（角チェリーは無効）。上段・下段にチェリーが見えても払い出さない。
