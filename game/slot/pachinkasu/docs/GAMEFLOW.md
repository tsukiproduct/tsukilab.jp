# ゲームフロー説明（実装の現状）

`docs/SPEC.md` は「こう作る」という設計書。こちらは**「今どう動いているか」**を書いたもの。
仕様書と実装が食い違っている箇所は §6 に一覧で挙げてある。

---

## 1. 1ゲームの流れ

```
① BET（3枚）
     ↓
② レバーON  ← ここで内部抽選（1/65536の乱数を1個引く）
     ↓        この瞬間に「今回何が当たったか」は確定している
     ↓        リールを止める操作では結果は変わらない
③ 演出（カットイン・フラッシュ）
     ↓
④ リール3つを停止  ← 制御表に従い、成立役を最大4コマすべりで引き込む
     ↓
⑤ 入賞判定・払い出し
     ↓
⑥ ボーナス入賞していれば → ボーナスへ
   していなければ → ①へ
```

**重要**: パチスロは「レバーを叩いた瞬間に当たりが決まる」方式。目押しは
「当たっているものを取りこぼさないため」の技術であって、目押しで当たりを増やすことはできない。

## 3. ボーナスが当たってから始まるまで

パチスロ特有の**2段階**になっている。ここが分かりにくいポイント。

```
【ステップ1】ボーナス成立（内部当選）
   レバーONでボーナスフラグを引く。
   でも、この時点ではまだボーナスは始まらない。
   画面には「チャンス!?」と出て、背景が前兆ステージに変わる。

        ↓ このあいだ「内部中」と呼ぶ。何ゲームか続くことがある

【ステップ2】ボーナス入賞
   ボーナス図柄（赤7揃い or BAR揃い）が実際に中段に揃うと発動。
   現在の実装は「オートビタ」なので、内部中にハズレを引いた
   次のゲームで自動的に揃う。
```

**リーチ目**: 単独BIG/単独REGを引いたゲームでは、左リール中段に7かBARが停止して
何も揃わない出目（＝リーチ目）が出る。この出目はハズレでは絶対に出ないように
制御しているので、**見えたらボーナス確定**。144通りある。

## 4. ボーナス中

**ボーナス中も自分でリールを打つ。** 消化役を毎回引き込むので取りこぼしは無い。
液晶にはそのボーナスの告知画面が固定表示され、その上に**累計獲得枚数が大きく出る**。
BET（3枚投入）は不要。

### BIG BONUS
- 赤7揃いで発動
- 1ゲーム **15枚**（スイカ揃い）
- 累計 **204枚** に到達したら終了 → **14ゲーム**（最終ゲームは端数の9枚）
- **5G目・9G目・13G目に「ビタ押しチャレンジ」**が発生（計3回）
- 終了時のAT当選率はビタの成功回数で変わる（下表）

### REG BONUS
- BAR揃いで発動
- 1ゲーム **8枚**（ベル揃い）
- 累計 **60枚** に到達したら終了 → **8ゲーム**（最終ゲームは端数の4枚）
- 技術介入なし
- 終了時に **1/16でAT当選**（当選時30G）

### ビタ押しチャレンジ（BIG中の技術介入）

「中リール 赤7を狙え！」と表示されたら、**中リールの中段に赤7が来る瞬間に停止ボタンを押す**。
**±1コマまで成功**。このゲームだけは制御でのすべりが効かず、押した位置がそのまま結果になる。

| ビタ成功回数 | 0回 | 1回 | 2回 | 3回 |
|---|---|---|---|---|
| AT当選率 | 40% | 55% | 70% | **AT濃厚** |
| 獲得G数 | +6G | +14G | +22G | +30G |

失敗しても救済で+2G/回が乗るため、全外しでも40%のAT抽選は受けられる。
BIG入賞時の1/64で発生する**フリーズはビタの結果に関わらずAT濃厚＋50G**。

> ボーナス中のゲームは投入不要なので、払い出し総枚数（204 / 60）がそのまま純増になる。
> これは `tests/simulate.js` の計算モデル（投入なしで一括加算）と一致している。
> AT当選率を50%→40%（全外し時）に変えたことで機械割は約0.4pt下がった
> （設定1: 95.4% → 95.0%）。技術介入の価値を出すための意図的な変更。

## 5. AT「MOON TIME」

- 純増 **約+0.5枚/G**（リプレイ確率アップ＋押し順ベルナビ）
- 初期 **40G**（＋BIG中のビタ獲得分、最大+30G）
- AT中にスイカを引くと **50%で+10G**
- AT中にBIGを引くと **+30G固定**
- 終了条件: 残りG数が0、または AT開始からの差枚+2400 / 1500G消化（完走）

設計思想は「AT自体の出玉は控えめにして、**AT中にボーナスを引いて延命する**ヒキ勝負」。
だからメインの65536テーブルはAT中も一切変わらない。

## 7. 検討事項

### 斜めラインを有効にできるか → **できる**

現行のリール配列のまま、有効ラインを5本（中段・上段・下段・右下がり・右上がり）に
増やせるか総当たりで検証した結果:

```
押下位置の全組み合わせ           : 9,261通り
ハズレ制御が不可能な組み合わせ   : 0通り (0.00%)
```

つまり「ハズレなのに斜めでベルが揃ってしまう」事故は、制御表を書けば**確実に避けられる**。
リール配列を作り直す必要もない。

ただし増やす場合は以下もセットで決める必要がある:
- **払い出しの再計算**: 有効ラインが5倍になると小役の当選機会も増えるため、
  テーブルのカウント値を下げないと機械割が跳ね上がる（`npm run sim` で要検証）
- **ライン表示**: どのラインで揃ったか分かるUI（現状は中段のみ光る）
- **チェリーの扱い**: 現在「左リール中段のみ有効」。角チェリー（上段・下段）を
  有効にするかどうか
