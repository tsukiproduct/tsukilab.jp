# スロットぱちんかす — Claude Code 作業指示書

A+AT仕様のパチスロシミュレーターアプリ。実機と同じ **16bit乱数・分母65536・減算方式** の内部抽選を再現している。

## 起動

```bash
npm run dev        # http://localhost:3000 で遊技（file://では動かない。ESモジュールのため要サーバー）
npm run sim        # 出玉検証（デフォルト100万G。低確率フラグの検定は200万G以上必要）
npm run test:reel  # リール制御の総当たり検証（全押下位置×全停止順）
node tests/simulate.js 10000000   # 本検証は1000万Gで実行
python tools/crop.py              # assets/_source/ から素材を再生成
```

操作: マウス／タップのほか、キーボードでも遊技できる（SPACE=BET→レバー、←↓→ or 1/2/3=停止、M=メニュー）。

### デバッグモード

```
http://localhost:3000/          通常モード（デバッグコードは一切読み込まれない）
http://localhost:3000/?debug=1  デバッグモード（左側にパネルが出る）
```

`?debug=1` のときだけ `src/ui/debug.js` が動的importされる。通常URLでは
debug.js へのネットワークリクエスト自体が発生しないので、本番挙動に影響しない。
**本番配布時は `src/ui/debug.js` を同梱しないこと**（import が失敗しても通常モードで動く）。

パネルでできること: 成立フラグの強制（単発/継続・全14フラグ+ハズレ）／フリーズ強制／
AT当選強制／AT即開始（G数指定）／状態リセット／クレジット設定／演出速度1〜20倍／
自動プレイ／内部状態のライブ表示。

デバッグ用の値は `main.js` の `export const DBG` に集約してある。
**`DBG.forceFlag` は抽選結果を上書きするため、通常の演出コードから書き込んではならない。**

## 構成と依存方向

```
src/core/     抽選エンジン・リール制御。純粋関数のみ。DOM・音・演出への依存を絶対に作らない
  tables.js       設定1〜6の65536テーブル、二次抽選(分母256)テーブル
  lottery.js      減算方式の抽選、内部中テーブル切替、払い出し計算
  reelControl.js  リール配列(STRIP)、有効ライン(LINES)、停止プラン決定、すべり制御、リーチ目判定
src/ui/       描画・入力・演出。core を呼ぶ側
  main.js       状態機械、遊技フロー、演出制御（現状ここにGame層が同居＝要分離）
  version.js    バージョン。タイトル画面に出る。**リリースのたびに更新し package.json と揃える**
  sound.js      効果音。WebAudioで合成する（音源ファイルは assets/se/）。鳴らすタイミングは main.js 側
  movies.js     液晶ムービー層。assets/movies/ に置くだけで再生、無ければ静止画へフォールバック
  debug.js      デバッグパネル。?debug=1 のときだけ動的importされる（本番には同梱しない）
  style.css
assets/       生成物。直接編集しないこと（tools/crop.py の再実行で消える）
  _source/      元のシート画像7枚。すべての素材はここから切り出す
  symbols/ bg/ announce/ cutin/ frame/   切り出し済み素材
  movies/       液晶ムービー置き場（README.md に規格と命名。crop.py の対象外）
  se/           効果音の音源ファイル置き場（crop.py の対象外・手で入れる）
tools/crop.py 素材切り出しツール。座標の正はここ
docs/SPEC.md  仕様書。数値の正はここ。実装と食い違ったら仕様書を正として直す
docs/STYLE.md スタイルガイド（レトロ4号機路線）。**素材を作る・差し替える前に必ず読む**
tests/
  simulate.js   出玉検証（実装準拠モデル。実装を変えたらここも合わせる）
  reel.js       リール制御の総当たり検証
```

**このプロジェクトは単体で完結している。** 外部フォルダ（旧版の `assets_work/` 等）を参照しないこと。

**依存方向は ui → core の一方向のみ。** 演出層が抽選結果に影響する経路を作らないこと（実機のメイン基板／サブ基板の分離に相当する）。

## リリース手順

### サイト用リポジトリへの同期

```bash
powershell -File tools/deploy_sync.ps1 -Dest <tsukilab.jp のクローン>
```

**`robocopy /MIR` は絶対に使わないこと。** 宛先を `game/slot/pachinkasu` に絞っていても、
リポジトリ全体のファイルを巻き込んで消す事故が起きた（2026-08-18・250ファイル消失。
コミット前だったため `git checkout` で復旧）。`deploy_sync.ps1` は `/E`（削除しない）で
コピーし、`game/slot/pachinkasu` の外に差分が出ていないか毎回チェックする。

### バージョン

サイトへ反映する前に `src/ui/version.js` の `VERSION` と `BUILD` を更新し、
`package.json` の `"version"` も同じ値に揃える。タイトル画面の下端に
`v0.3.0 (2026-08-13)` の形で出るので、**GitHub Pages のキャッシュで
古い版を見ていないか**をここで判別できる（デバッグ版は末尾に `DEBUG` が付く）。

## 絶対に守るルール

1. **テーブル値を変えたら必ず `npm run sim` を実行**し、機械割が目標から外れていないか確認する。目標は設定1 ≒95.2% / 設定6 ≒102.9%（技術介入なし）。
   **上乗せ・エンペラーの分散が大きいので判断は300万G以上で行う**（100万Gだと±0.5pt揺れる）
7. **有効ラインは5本だが、払い出しは成立役に対して1回**。ラインごとの重複払い出しにすると
   テーブルを全面的に引き下げる必要があり、機械割の調整が追えなくなる。`payoutOf()` を唯一の払い出し口に保つ
2. `assertTables()` を通らない変更（合計が65536超）はマージしない
3. 乱数は `crypto.getRandomValues` を使う。`Math.random` を抽選に直接使わない
4. 重複当選（小役+ボーナス）は**独立したフラグ**として扱う。「小役当選後に二次抽選」に書き換えない
5. **著作権**: 実在の機種名・キャラクター名・楽曲名・メーカー名をコード、コメント、アセット名、UI文言に一切含めない。すべてオリジナル表現にする
6. 実銭を賭ける機能は実装しない。あくまでシミュレーター

## 現状の実装状況

実装済み:
- 65536抽選（設定1〜6）、フラグ持ち越し、内部中テーブル
- **有効ライン5本**（中段・上段・下段・右下がり・右上がり）。払い出しは役に対して1回
- **スイカの強弱**（弱=右下がり / 強=中段揃い。強のみボーナス重複あり）
- 3リール表示、停止操作、小役判定と払い出し
- BIG(204枚)/REG(60枚)、BIG中ビタチャレンジ、AT「MOON TIME」（純増+0.5枚/G）
- **AT中のレア役上乗せ**（`drawATUpgrade`。強スイカのみ50G以上）、AT中BIGで+30G、完走(差枚+2400)
- **エンペラータイム**（特化ゾーン。ビタ3回成功で濃厚、継続率80%で1勝+20G）
- **楽曲選択**（BIG開始前とAT中。ペルソナ5風UI。選択は localStorage に保存）
- 状態別背景切替、カットイン3段階、告知画面、設定6示唆
- ボーナス確定演出（カットイン→溜め→「BONUS 濃厚」の3段。成立ゲーム45%／内部中は毎G8%で告知）
- 設定変更メニュー、データ表示
- 効果音（`src/ui/sound.js`・WebAudio合成。役ごとに入賞音を分け、払い出し枚数ぶんメダル音を鳴らす）
  - 音源ファイルも鳴らせる（`assets/se/`。BIG/REGの確定音を配置済み。無ければ合成音へ）
- ボーナス／AT中のMV再生（`mv_song1` / `mv_song2` を選択。ボーナス→ATで途切れず継続）
- REGボーナスのBGM（`assets/se/bgm_reg.mp3`。REGは映像を持たないので音のみ）
- ボーナス／AT終了時のリザルト画面、AT終了3G前からのカウントダウン（3→2→LAST）

- リール制御表（`src/core/reelControl.js`・最大4コマすべり・詰み回避の先読み付き）とリーチ目560通り
- 液晶ムービー層（`src/ui/movies.js`。ファイルを置けば自動再生）
- 素材のスタイルガイド化（`docs/STYLE.md`）。下パネル・図柄はレトロ4号機のフラットイラスト、
  筐体ハードウェア（ベゼル・ボタン・レバー・7セグ枠）は§5.5の例外で実写寄りの質感に統一済み

未実装（優先順）:
1. **目押し** — 現状オートビタ（`controlStop()` の `assist=true`）。`assist=false` にすると4コマすべりのみになり「こぼし」が発生する。手動目押しモードと図柄スロー表示の補助機能を作る
2. **前兆・連続演出** — `bg_koukaku`（高確ステージ）が未使用のまま。高確／前兆の内部状態を作り、連続演出（`movies.js` の `renzoku_*` キーが予約済み）に繋ぐ
3. **エフェクト** — `assets/_source/` の 16_41_45 にスプライトシート（雷・7炸裂・紙吹雪・リング 各8コマ）がある。緑背景(#00FF00近似)なのでクロマキー抜きしてスプライトアニメ化する
4. **Game層の分離** — `src/ui/main.js` に状態機械が同居している。`src/game/stateMachine.js` `src/game/atManager.js` に切り出す
5. **セーブ** — localStorage で総G数・BIG/REG回数・差枚・スランプグラフを永続化
6. **サウンド** — 現状は `sound.js` の合成音。BGM と、オリジナル録音音源への差し替えが未対応
7. **機械割の微調整** — 300万G実測で 設定1 95.8% / 設定6 103.7%。設定6が目標102.9%に対し
   まだ +0.8pt 高い。上乗せ・エンペラーを入れた際に AT初期G(40→20/16)と SOLO_REG設定6(128→100)で
   105.6%→103.7% まで下げたが、残りはボーナス確率そのものに起因する。
   **エンペラーの幾何分布の裾で分散が大きく、500万G以下の測定は ±0.4pt 揺れる**ので、
   調整の判断は必ず300万G以上で行うこと

## コーディング規約

- 日本語コメントで意図を書く。特に確率・出玉に関わる箇所は「なぜこの値か」を残す
- 数値のマジックナンバー禁止。確率は必ず `tables.js` に集約する
- スマホ縦持ち（iPhone想定）が主ターゲット。タップ領域は48px以上、リールの視認性を最優先
